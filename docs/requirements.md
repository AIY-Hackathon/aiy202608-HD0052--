## 1. 引言

### 1.1 项目背景

基因分析助手网站（Gene Analysis Assistant Website）是一套服务于基因分析与遗传咨询的综合性 Web 应用平台。系统围绕三个相互关联的核心模块构建：（1）基因报告自动分析；（2）基因-环境交互模拟；（3）个性化生活方式建议。

本项目依托 ClinVar、OMIM、PharmGKB、OncoKB 以及 CNGBdb 等权威医学数据库，遵循 BGI（华大基因）技术标准与医学遗传学最佳实践，提供精准的基因风险评估与临床决策支持。

> **⚠️ 重要免责声明**：本产品为教育研究型项目，**不构成医疗器械**，**不提供临床诊断**。所有 AI 生成的基因解读仅供学习和参考目的，不得替代专业医疗建议。详见 [§6 FDA AI/ML 合规与免责声明](#6-fda-aiml-合规与免责声明)。

### 1.2 适用范围

本需求规格说明书面向以下读者群体：

## 4. 系统需求

### 4.1 基因报告上传与分析 — 优先级 P0 🟢

**用户故事**：作为用户，我希望能上传自己的基因报告，以便获得基因信息的详细分析及相关疾病风险评估。

#### 验收标准

1. 当用户上传有效的基因报告文件（VCF/TSV 格式）时，上传处理器应校验文件格式和内容
2. 校验通过后，报告解析器应提取基因变异和元数据
3. 变异匹配器应针对每个提取到的变异，向医学数据库（ClinVar、OMIM、dbSNP）发起查询
4. 对所有已匹配的变异，风险计算器应使用经过验证的 PRS 公式计算基因风险评分
5. 分析生成器应将结果整合为综合性的分析报告
6. 当医学数据库对某个变异没有返回匹配结果时，系统应将该变异标记为待人工复核
7. 系统应对所有报告的上传和分析操作保留审计日志

---

### 4.2 遗传病携带者筛查 — 优先级 P3 ⚪（可选 / 后续迭代）

> **设计变更说明**：原"基因兼容性评估"（Partner Selector / 伴侣选择器）已重新定位为"遗传病携带者筛查"。该功能评估单个用户的隐性遗传病携带状态，帮助用户了解自身是否携带可能在生育中遗传给后代的致病变异。原"伴侣兼容性"涉及的择偶优生学语境已移除，改为符合医学伦理的标准携带者筛查（Carrier Screening）范式。该功能仅在充分告知用户并获取明确同意后方可启用。

**用户故事**：作为了解自身遗传健康信息的用户，我希望进行遗传病携带者筛查，以便了解自身是否携带可能影响后代健康的隐性遗传变异。

#### 验收标准

1. 在用户提供基因型数据并给予明确同意的情况下，系统应识别可报告的隐性遗传病携带变异
2. 携带者筛查结果应遵循 ACMG SF v3.1 推荐报告基因列表
3. 系统应使用孟德尔遗传模型计算后代患病概率（仅当用户主动请求时）
4. 对高风险结果，系统应提供详细的遗传咨询资源链接
5. 结果展示应使用标准化的遗传咨询术语，避免歧义
6. 系统应提供明确的"退出"选项，允许用户随时停止筛查并删除相关数据

---

### 4.3 交互式健康模拟 — 优先级 P1 🟡

**用户故事**：作为用户，我希望模拟自身基因与生活方式因素的交互作用，以便可视化潜在的健康结果，做出明智的生活方式选择。

#### 验收标准

1. 健康模拟器应保持健康指标的实时计算
2. 当环境因素滑块调整时，GxE 模型应重新计算风险预测
3. 可视化引擎应使用 D3.js / Recharts 在每次参数变化时更新健康轨迹图
4. 存在遗传易感性时，系统应建模不同生活场景下的疾病进展
5. 模拟控制器应支持保存和对比多个模拟场景
6. 对于所有模拟结果，系统应基于证据强度提供置信区间
7. 环境因素范围应始终处于生物学合理限度内

---

### 4.4 个性化生活方式建议 — 优先级 P1 🟡

**用户故事**：作为用户，我希望基于自己的基因档案获得有科学依据的个性化生活方式建议，以便降低疾病风险、优化健康状况。

#### 验收标准

1. 基于用户的基因风险档案，建议引擎应生成个性化生活方式建议
2. 每条建议应关联支撑科学文献或数据库（PharmGKB、ClinVar）
3. 存在矛盾的证据时，系统应提供平衡的视角并注明证据强度
4. 建议按潜在影响和实施难度排序
5. 用户可跟踪已采纳建议的进展

---

### 4.5 数据隐私与安全 — 优先级 P0 🟢

**用户故事**：作为用户，我希望自己的基因数据得到安全、保密的处理，以便隐私得到保护，数据不被滥用。

#### 验收标准

1. 所有基因数据传输和存储实施加密（HTTPS + 本地加密存储）
2. 存储数据时使用与个人信息分离的匿名化标识符
3. 访问控制器强制执行基于角色的访问控制
4. 当用户拒绝同意时，系统应阻止数据处理
5. 涉及数据共享时，系统应获取明确的、知情后的同意
6. 审计日志器记录所有对基因数据的访问和修改

---

### 4.6 用户界面与体验 — 优先级 P0 🟢

**用户故事**：作为用户，我希望拥有直观且视觉吸引的界面，以便轻松浏览复杂的基因信息，理解分析结果。

#### 验收标准

1. UI 实现桌面、平板和移动端的响应式设计
2. 复杂基因概念通过可视化工具包提供交互式说明
3. 导航流程通过清晰的进度指示引导用户完成分析步骤
4. **AI 生成内容必须透明标注**：所有 AI 生成的解读/建议须附带醒目的"🤖 AI 生成"标签和免责声明
5. 核心交互响应时间维持在 2 秒以内
6. 错误消息提供有帮助的、可操作的提示以及恢复选项

**AI 内容标注规范**：

| AI 内容类型 | 标注方式 | 示例文案 |
|------------|----------|----------|
| 变异解读 | 黄色 "🤖 AI 辅助解读" 标签 + 信息图标 | "本解读由 AI 模型生成，仅供参考，不构成临床诊断。" |
| 健康建议 | 蓝色 "📋 AI 生成建议" 标签 | "以下建议基于基因数据自动生成，请在采纳前咨询医疗专业人员。" |
| 风险评估 | 橙色 "⚠️ 统计估算" 标签 + 置信区间 | "该风险值为统计估算，置信区间见右侧图表。" |
| 教育内容 | 绿色 "📖 学习资料" 标签 | "本内容来自公共医学数据库，仅为科普目的。" |

### 4.7 医学数据库集成 — 优先级 P0 🟢

**用户故事**：作为系统管理员，我希望可靠地集成医学遗传学数据库，以便系统提供准确且最新的基因信息。

#### 验收标准

1. 数据库连接器应维持与 ClinVar、OMIM、PharmGKB 和 dbSNP 的连接
2. 缓存管理器应在优化查询性能的同时保证数据时效性（24 小时同步周期）
3. 数据库之间存在不一致时，应用基于证据的解决规则（ClinVar 星级评审优先）
4. 数据库中断期间使用本地缓存数据继续运行

**关键数据库资源**：

| 数据库 | 维护机构 | 核心用途 | 访问方式 | 本地缓存路径 |
|--------|----------|----------|----------|-------------|
| ClinVar | NCBI | 变异致病性分类 | E-utilities API / FTP 批量 VCF | `data/clinvar/` |
| OMIM | Johns Hopkins | 遗传病-基因关联 | Web 查询 | 缓存至 PostgreSQL |
| PharmGKB | Stanford/NIH | 药物基因组学 | REST API | 缓存至 PostgreSQL |
| 1000 Genomes | IGSR（CNGBdb 镜像） | 人群频率参考 | FTP 下载 | `data/1000genomes/` |
| GIAB | NIST（CNGBdb 镜像） | 基准标准品 | FTP 下载 | `data/giab/` |
| RefSeq | NCBI（CNGBdb 镜像） | 参考序列 | FTP 下载 | `data/refseq/` |
