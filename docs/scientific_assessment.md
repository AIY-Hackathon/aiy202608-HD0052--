## 2. 基因分析板块逻辑

### 2.1 数据流

```
用户上传 VCF → 文件校验 → VCF 解析（pandas）
    → 基因识别（GENEINFO 字段）
    → ClinVar 注释查询（本地 440 万变异库）
    → 关键基因抓取（综合评分排序）
    → 科学分析（遗传负荷 + 维度 + 总结）
    → Mini-PRS 引擎（GWAS 效应量加权）
```

### 2.2 关键基因抓取逻辑

综合评分 = **变异严重度 × 证据权重 × 基因重要性**

| 因子 | 说明 |
|------|------|
| 变异严重度 | Pathogenic(0) > VUS(1) > Benign(2) > 其他(3) |
| 证据权重 | GWAS 确认=1.0 / 候选基因=0.7 / 弱证据=0.4 |
| 基因重要性 | 维度/疾病相关基因 ×2 |

### 2.3 Mini-PRS 引擎（科学性核心）

- **Tier 1（量化）**：GWAS 确认的 SNP，如 FTO rs9939609，用 beta × 风险等位基因数计算
- **Tier 2（调节）**：生物学功能明确的基因，如 CLOCK/ACTN3，提供解释不评分
- **APOE 单倍型**：rs429358 + rs7412 联合解析出 ε2/ε3/ε4，独立风险修正

### 2.4 局限说明

- 覆盖 **7 个 SNP × 4 基因**（教育演示范围）
- 未纳入全基因组（教育定位，非临床诊断）
- 基因型从 VCF 变异推断（杂合假设）

## 3. 环境交互板块逻辑

### 3.1 当前实现（简化版）

```
前端因素滑块（sleep/exercise/diet/stress）
    → POST /api/simulate
    → prs_calculator.calculate_health_score(factors)
    → 健康评分（0-100）+ 维度 + 趋势
```

**公式（当前）**：
```
健康分 = 遗传基线(72) + Σ(因素偏差)
  sleep:   ((sleep-6)/7) × 8
  exercise:((exercise-3)/7) × 10
  diet:    ((diet-5)/9) × 12
  stress:  ((6-stress)/9) × 10
```

### 3.2 引擎能力（已实现但未接入）

Part C 的 `engine/gxe_model.py` 提供更科学的版本：
- **HTI（健康轨迹指数）**：基因 + 环境 + 交互 + 时间
- **维度评分**：metabolic/cognitive/athletic/sleep 各自计算
- **因子分解**：基因贡献 / 环境贡献 / 交互贡献
- **置信区间**：不确定性量化

### 3.3 逻辑问题（需改进）

| 问题 | 说明 |
|------|------|
| **未接入 GxE 引擎** | simulate.py 用简化公式，没用 Part C 的 gxe_model |
| **遗传基线固定 72** | 未使用用户真实基因档案 |
| **无交互项** | 公式是纯环境加法，没有基因×环境交互 |
| **无时间衰减** | 趋势是线性，未模拟随时间变化 |

## 4. 科学性优势与短板

### 优势
1. ✅ 数据来源真实可靠（ClinVar/PDB/GWAS）
2. ✅ 关键基因抓取逻辑清晰
3. ✅ 证据追溯完整（PMID/置信度）
4. ✅ 真实 3D 蛋白结构（非示意图）
5. ✅ 多人种真实频率数据

### 短板
1. ❌ **GxE 引擎未接入**（最大短板）
2. ❌ 遗传基线固定，未个性化
3. ❌ 交互项缺失
4. ❌ 覆盖基因有限（4-7 个）
5. ❌ 无人群分层参考（当前用默认频率）

| 优先级 | 改进 | 说明 |

**科学性整体良好**（4/5）：数据真实、框架清晰、证据可追溯。核心短板是**环境交互板块未接入真正的 GxE 引擎**——这是提升科学性的首要任务。
